Dockerized ETL Pipeline

A containerized ETL pipeline built with Python, Pandas, PostgreSQL, Docker, and Docker Compose.

This project demonstrates a complete local data engineering workflow: extracting data from CSV files, transforming and validating records, handling rejected data, and loading clean data into PostgreSQL.

ETL Pipeline
1. Extract

The pipeline reads two CSV datasets:

customers.csv

orders.csv

2. Transform

Customer spending values are converted to numeric values using Pandas.

df["total_belanja"] = pd.to_numeric(
    df["total_belanja"],
    errors="coerce"
)


Invalid numeric values are converted to NaN.

3. Validate

Customer records are separated into two groups:

Clean records — valid total_belanja

Rejected records — missing or invalid total_belanja

Rejected records are written to a separate CSV file instead of being silently discarded.

4. Load

Clean customer records are loaded into PostgreSQL:

customers


Order records are loaded into:

orders


The required tables are created automatically when they do not already exist.

Docker Compose Services

The application uses two services.

ETL

The ETL container runs the Python application.

Host directories are mounted into the container:

./data:/app/data
./output:/app/output


This allows the application to read input files and write generated output files.

PostgreSQL

PostgreSQL runs as a separate container with persistent storage:

postgres_data:/var/lib/postgresql/data


The named volume keeps database data available across PostgreSQL container recreation.

Environment Configuration

Configuration is provided through environment variables.

Create a local .env file based on .env.example:

APP_ENV=development

POSTGRES_HOST=postgres
POSTGRES_PORT=5432
POSTGRES_DB=project05
POSTGRES_USER=etl
POSTGRES_PASSWORD=etlpassword


The .env file is excluded from Git to prevent local configuration and credentials from being committed.

Getting Started
Prerequisites

Make sure the following are installed:

Docker

Docker Compose

1. Clone the repository
git clone git@github.com:bimztwenty20/project-05-docker.git
cd project-05-docker

2. Create environment configuration
cp .env.example .env


Review the values in .env before starting the application.

3. Start PostgreSQL
docker compose up -d postgres


Check the service status:

docker compose ps


PostgreSQL should eventually show:

Up (healthy)

4. Run the ETL pipeline
docker compose run --rm etl

Service Dependency

The ETL service waits for PostgreSQL to become healthy before starting:

depends_on:
  postgres:
    condition: service_healthy


PostgreSQL uses pg_isready as its healthcheck:

healthcheck:
  test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]


This ensures the ETL process does not attempt to connect before PostgreSQL is ready to accept connections.

Persistence

PostgreSQL data is stored in a named Docker volume:

project-05-docker_postgres_data


This separates database storage from the lifecycle of the PostgreSQL container.

The persistence workflow was tested by:

Loading the ETL data.

Verifying 7 customers and 4 orders.

Recreating the PostgreSQL container.

Starting PostgreSQL again.

Verifying the data remained available.

This demonstrates persistent database storage using Docker volumes.

Avoid docker compose down -v if you want to preserve the PostgreSQL data volume.
